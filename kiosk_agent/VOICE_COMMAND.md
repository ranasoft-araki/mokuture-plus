# 声で操作する（実験導入）

キオスクの画面を「ほうもん」「ロッカー」「もどる」のような短い言葉で操作する実験機能。
設計は `Doc/kiosk-voice-touchless.html` の段階2。**端末の中だけで完結**し、クラウドの
音声認識 API・Web Speech API・生成 AI は使わない。インターネットが切れていても動く。

- **押さなくても音声モードに入る**（`command.auto_start: true`・既定）。待機画面から
  ようこそ画面へ進んだ時点で聞き取りを始め、待機画面へ戻ると抜ける。来訪者が
  「声の操作をやめる」を押したら、その人の間（待機画面へ戻るまで）は自動では入らない。
  `auto_start: false` にすると、帯の「声で操作する」を押したときだけ入る
- マイクを開けるのは**画面が選択を待っている間だけ**。**待機画面（動画）では開けない**ので、
  前を通る人の会話を聞き続けることはしない
- 画面のボタンは**ほぼすべて声でも押せる**（2026-10-02 に範囲を広げた）。ただし人が動く・物が動くもの
  （受付の送信・担当者を呼ぶ・配達の呼び出し・ロッカーの空きの口・扉を閉めました）は、**声で選んだときだけ
  「〜しますか？ はい／いいえ」の確認を挟む**。**暗証番号の画面ではマイクを開けない**。文字を打つキーボードも声の対象外
- 使えない端末（マイク未接続・モデル未取得・サービス停止）では「声で操作する」が
  **表示されない**。受付は従来のタッチ操作だけで完了できる
- **表示言語（日本語／English・下部帯のタッチ切替）に声の言語も追従する**（§12）。
  発話で言語を自動判定する仕組みは無い。英語の声は**英語の Vosk モデルを端末へ手動導入した
  ときだけ**使える（OTA では配らない）。未導入の端末は英語表示でも声は使えない（タッチは使える）

> 以前あった「音声で入力」（受付フォームを声で埋める・一文の名乗り）は 2026-09-29 に削除した。
> whisper.cpp・クラウド中継（AmiVoice）・担当者の読み仮名（staff_readings.yaml）もあわせて削除。

## 1. 構成

```
ブラウザ (kiosk.html)              画面ごとの言葉を登録・状態表示・当たった要素を押す
   │  http://127.0.0.1:8181        ← localhost 限定
   ▼
音声サービス (mokuture-voice)       マイク制御・VAD・Vosk(語彙を絞って decode)  ← 別プロセス
   │                                127.0.0.1 にのみ bind
   └─ arecord (ALSA)                USB マイクから 16kHz/モノラル/16bit
```

キオスク本体（`main.py` / port 8080 / 0.0.0.0）とは**別プロセス・別ポート・別 systemd**。

| 理由 | 内容 |
|---|---|
| 外部から触らせない | 本体は端末管理のため `0.0.0.0` で待ち受けている。相乗りすると音声 API が LAN から見えてしまう。別プロセスなら `127.0.0.1` に bind でき、**ソケットの時点**で閉じられる |
| 巻き込まない | 実験機能が落ちても受付本体（GPIO・ロッカー・扉）は動き続ける。画面から「声で操作する」が消えるだけ |

コードは `kiosk_agent/voice/` にあるので **OTA で配信できる**。本体の再起動では別プロセスの
音声サービスは入れ替わらないため、音声サービスが自分のソースのハッシュ変化を検知して
自ら終了し、systemd に起こし直してもらう（`voice/server.py` の `_watch_sources`）。

API（すべてループバックからのみ）:

| | |
|---|---|
| `GET /voice/status` | 使えるか（マイク・Vosk・語彙を絞れるモデルか） |
| `POST /voice/session` | 音声モードに入ったとき |
| `POST /voice/session/{id}/command` | 画面の選択肢 `{screen, choices:[{id, phrases}], fallback}` のどれが言われたかを 1 回聞く |
| `GET /voice/session/{id}/state` | `command: {matched, confidence, reason}`。**認識した言葉そのものは返さない** |
| `POST /voice/session/{id}/cancel` / `DELETE /voice/session/{id}` | 取り消し / 破棄 |
| `GET /voice/metrics` / `GET /voice/devices` | 集計 / マイク一覧 |

## 2. インストール（Raspberry Pi）

前提: Raspberry Pi 4 (4GB) 以上 / Raspberry Pi OS 64bit / **USB マイクを接続済み** /
キオスクエージェント（`install.sh`）が導入済み。導入時だけネットワークが要る。

```bash
cd ~/mokuture/kiosk_agent
bash scripts/install_voice.sh
```

やること: Vosk のモデルの確認と取得（取得元と SHA-256 は `fetch_voice_models.py` に固定。
git-lfs は不要）→ `alsa-utils` → `vosk` を venv へ → モデルの展開 → `voice_input.yaml` を
雛形から作成 → `audio` グループへ追加 → `mokuture-voice.service` を登録して起動。

動いているか:

```bash
curl -s http://127.0.0.1:8181/voice/status
```

`available: true` なら画面下部の帯に「声で操作する」が出る。`false` のときは
`microphone.detail` / `command.detail` に理由が入っている。

**以前「音声で入力」を入れた端末**には whisper.cpp のビルド結果（`vendor/`）や
`staff_readings.yaml`（実在の社員の読み）が残っている。使われないが、消すなら:

```bash
cd ~/mokuture/kiosk_agent
rm -rf vendor staff_readings.yaml voice_models/ggml-*.bin
```

## 3. 画面での動き

- 声で選べるボタンには、**押す前から**「言う言葉」の札が薄く付く（🎤「あずける」）。
  声で操作したことの無い人にも「声でも選べる・何と言えばよいか」が画面で分かるように
  するため。自動で入る設定（既定）では最初から札が濃く、帯に「お話しください」と赤点が出る
- 赤点が出ている間だけ聞いている。赤点が消えている画面（暗証番号など）では聞いていない
- 自動で入ったときは開始音を鳴らさない（前を通っただけの人に毎回鳴るため）。マイクが
  使えなかったときも来訪者には知らせず、10 分間は自動で入らない（帯に「声で操作する」が出る）
- 「声の操作をやめる」を押すと帯が「声で操作する／押してから話してください」に戻る。
  押せばまた入れる（このときは開始音が鳴る）
- 札の言葉は**読み仮名（ひらがな）**。「預ける」「置き配」のように読みに迷う漢字は書かない
- 当たるとボタンが一瞬光り、押したのと同じことが起きる（タッチと同じ処理）
- どれにも当たらなければ**画面は動かない**。「もう一度お願いします」を 1 回だけ出す
- 話している間は待機画面へ戻る秒読みが延びる。「まだご利用中ですか？」が出たら「つづける」

| 画面 | 札の言葉 | 札どおりでなくても通る言い方 |
|---|---|---|
| ようこそ | うけつけ | お願いします / すみません |
| ご用件 | ほうもん / はいたつ / ロッカー | ご訪問・一番 / 荷物・二番 / 三番 |
| ロッカーの種別 | あずける / うけとり | 保管・手荷物 |
| ロッカーの口（預ける・受け取る・置き配） | いちばん 〜 ななばん | 「にばんのロッカー」 |
| 確認（下の表） | はい / いいえ | 開ける / やめる |
| 配達の方法 | おきはい（空きがあるときだけ）/ よびだし | |
| 受付フォーム | めいし / うけつけする /（札なし）ご用件・部署のボタンの文字そのまま | 受付・送信 |
| 名刺の読み取り | さつえい / もどる | 撮影する |
| 解錠ガイド（預ける・置き配） | しめました / やめる | 扉を閉めました |
| 解錠ガイド（受け取り） | わかりました / やめる | 完了 |
| 担当者を呼んだあとの案内 | とじる | わかりました |
| お待ちください（応答待ち） | やめる | |
| 結果画面 | （札なし）わかりました / やめる | 完了 |
| アンケート | （札なし・選択肢の文言そのまま）/ スキップ | 回答せず終了 |

共通語 = もどる（下部帯の「← 戻る」）/ やめる（下部帯の「やめる」）/ たんとうしゃをよぶ（下部帯の
「担当者を呼ぶ」。呼んでください・助けて でも通る）/ さいしょから（ようこそ画面へ）/ つづける（待機画面へ
戻る前の確認に答える）。言葉の一覧は `kiosk.html` の `VOICE_VOCAB` が唯一の定義。札は、押せば声の操作に
入れる画面（帯に「声で操作する」がある画面）でだけ押す前から出す。

ご用件・部署・アンケートの選択肢は管理画面で変わるので、**ボタンの文字をそのまま**言葉にする。
発音辞書の語で書けない文言・16 文字を超える文言はその選択肢だけ声で選べない（画面のほかの言葉は使える）。
部署は押すたびに選択／解除が切り替わるボタンなので、声では「選ぶ」だけにする（選択中の部署を言っても外れない）。

### 声で選んだときだけ確認を挟むもの

雑談の誤爆で人が呼ばれたり錠が動いたりしないように、次の操作は**声で選んだときだけ**
「〜しますか？」の確認を出し、「はい」（声でもタッチでも）で実行する。タッチで押したときは従来どおりすぐ動く。

| 操作 | 確認の言葉 |
|---|---|
| 「担当者を呼ぶ」（下部帯） | 担当者を呼びますか？ |
| 配達の「呼び出し」 | 担当者を呼び出しますか？ |
| 受付フォームの「受付する」 | この内容で受付しますか？（お名前・会社名・ご担当を並べて見せる＝復唱。お名前が空なら確認を出さずにタッチと同じエラー） |
| ロッカーの空きの口 | A（上段）を開けますか？ |
| 解錠ガイドの「扉を閉めました」 | 扉を閉めましたか？（錠をかけて、暗証番号の設定 / 担当者への通知へ進む） |

### 声では押さないもの

| 操作 | 理由 |
|---|---|
| 暗証番号 | ロビーで番号を読み上げさせない。**この画面ではマイクを開けない**（帯の「担当者を呼ぶ」もこの画面では声にしない。マイクが開いていると番号を話してよいと受け取られる） |
| 受付フォームのキーボード・漢字の変換候補・担当者の選択 | 文字を打つ操作。声で文字を入れる機能（音声で入力）は 2026-09-29 に削除した |

## 4. 当たり方（実測）と、その対策

Windows の合成音声（`scripts/voice_command_eval.py`）で測った。

| 見たもの | 結果 |
|---|---|
| 画面への操作 222 発話（札のひらがな・「えーと、〜」「〜でお願いします」込み） | 当たり 218・取り違え 0（外れはご用件の「二番」「三番」だけ） |
| ロッカー 7 口の番号（語彙を絞って外れたら通常の認識で聞き直す） | 25/28（聞き直しなしでは 11/21） |
| 無関係な雑談 28 本 × 7 画面 | 誤爆 7（「ちょっと待って」→つづける 等、意味どおりのもの） |
| 2026-10-01 の修正後（8 画面・288 発話／雑談 28 本 × 8 画面） | 当たり 278（直す前 277）・取り違え 0・誤爆 8（直す前 8） |
| 認識時間 | 中央値 63ms / 画面ごとの初回 0.1〜0.4 秒（Windows） |

効いた対策（どれも `voice/vosk_engine.py` に理由を書いてある）:

- **句ではなく語で絞られる**。「三 番」と書いても「三」だけが返るので、句が続けて現れたかを
  こちらで確かめる。辞書の切り方が 2 通りある言葉（お 願い します / お 願い し ます）は
  続けた文字列で比べる
- **同じ読み・近い音の表記を並べない**。「戻る」と「もどる」を両方入れると信頼度が 0.5 ずつに
  割れて両方外れた。「受け取る」と「受け取り」も割れた
- **雑談に紛れたキーワードは信頼度 1.0 で当たる**（「ロッカーの鍵どこだっけ」）。しきい値では
  切れないので、**キーワードの後ろに語彙外の発話が 0.25 秒以上続いたら捨てる**
  （`command.trailing_unk_sec`）。これで誤爆 31 → 7
- **短い数字は発話頭の雑音に吸われる**（語彙を絞ると「にばん」は「番」だけが残る）。
  ロッカーの画面だけ、外れたら語彙を絞らない通常の認識で聞き直す（`command.fallback_min_conf`）。
  聞き直しの結果にも「文の一部なら捨てる」を同じようにかける
- 話し終わりとみなす無音は 0.7 秒。0.5 秒だと「えーと、預ける」が「えーと」で切れて取り違えた

### 録音の始まりと終わり（VAD）

実機で「生活音のある場所だと、話している最中に認識が始まる」と分かった（2026-10-01）。
原因は暗騒音の見積もりで、**窓を開けるたびに固定の -55 dBFS から始めていた**。それより 9dB
以上うるさい場所では、窓を開けた最初の 1 コマ（20ms）が「話し始め」になり、話していると
判定している間は暗騒音を学ばないので、**声と関係なく窓を開けた 3 秒後（`max_record_sec`）に
切れていた**。直したこと（`voice/vad.py`）:

- 暗騒音は**話し始める前の直近 2 秒の音の中央値**で見積もる（`vad.noise_floor_window_ms`）。
  開始音ガードの間の音も入れる。履歴は窓をまたいで持ち回る（`vad.noise_floor_memory_sec`）＝
  窓を開けた瞬間にもう話している人の声を暗騒音と取り違えない。上限まで声が続いたら
  見積もりが低すぎた疑いがあるので履歴を捨てて測り直す
- 話し始めは**直近 0.2 秒のうち 0.1 秒以上が「声らしい大きさ」（暗騒音＋5dB・`vad.silence_margin_db`）で、
  そのどこかで「声の大きさ」（＋9dB・`vad.speech_margin_db`）を越えた**ときに決める（`vad.onset_ms`）。
  ドア・足音・咳では始めない。声らしいコマは暗騒音に入れない
- **2026-10-01 夕方の手直し（実機で「かなりマイクに近づかないと認識しない」）**: 当初は「＋9dB が 0.1 秒」を
  求めていて、少し離れて話した声（判定ラインすれすれ）で録音が始まらなかった。さらに、話し始めに
  ならなかった小さめの声を暗騒音に入れていたので言い直すほどハードルが上がり、話している最中も
  ＋9dB 未満の声で暗騒音を追っていたので小さめの声は語尾の前で「話し終わり」になった。3 つとも直した。
  話している最中に暗騒音を追うのは＋5dB 未満のコマだけ。**話し終わりも＋5dB の線で見る**（始まりは高い線・
  終わりは低い線。webrtc の判定のときは従来どおり）。あわせて、話し終わりに足す「声の直後の 0.25 秒」が
  実際には「無音の最後の 0.25 秒」になり、語尾の直後 0.46 秒ほどが抜けていた書き間違い（以前から）も直した
- 独立の検証（雑音 8 種・声 -30〜-48dBFS）: 8 割以上を声の頭で拾えるいちばん小さい声は、どの雑音でも直す前と
  同じかそれ以上で、午前の版より 2〜4dB 小さい声まで拾う。声の区間を丸ごと録れた本数は 73（直す前）・78（午前の版）
  → 222（280 本中）、Vosk の当たりは 82・89 → 105。キーワード全体 279/288・取り違え 0・誤爆 7/224
- **引き換え**: 近くの雑談の中や暗騒音が急に上がった直後は、3 秒の上限まで録る回数と、話し終わってから閉じる
  までの遅れが増える（雑談を流し続けて窓を開け直す試験で、上限で切れた窓 59 → 97、当たりは 148 → 155 で
  落ちない）。雑談の部屋では 1 回目の言い直しを取りこぼしやすい
- 履歴が無いとき（サービス起動直後・60 秒聞いていない・上限で切れた直後）は、**本物の音を 0.1 秒
  測ってから判定する**。0 埋めのコマ（マイクが開いた直後など）は数えない。数えると、0 のあとに
  大きな暗騒音が続く場合に測らないまま判定を始める
- **ノイズゲート付きのマイク**（無音を 0 で返す）は、**音が鳴ったあとに 0 が 0.3 秒続く**のを一度見たら
  覚えておき、以後は 0 が 0.3 秒続いた窓を静かな部屋とみなして、測らずに固定の初期値以下で判定する
  （履歴に声の頭を覚えていても初期値より高くは見積もらない）。0 を数えないだけだと、そういうマイクでは
  毎回声の頭を暗騒音として測って声を拾えない（合成音声で 176/180 → 15/180、見分けた後は 180/180）。
  **窓の頭の 0 だけでは決めない**: マイクが開いた直後だけ 0 を返す機材だと、うるさい部屋でも静かな部屋に
  なって元の打ち切りに戻り、窓ごとに繰り返す（独立の検証で、0 が 0.3 秒以上→ -40dB で全窓打ち切りだった）
- **割り切り**:
  - 履歴が無い窓で、窓を開けた瞬間から話し始めると、声の頭を暗騒音として測ってしまい拾えないことが
    ある（話し始めが 0.1 秒後でも開始が 0.46 秒遅れた）。画面が出てから話すまでには間があるので実害は
    小さいと見ている
  - ノイズゲートのマイクでは、起動後にゲートが閉じるのを一度見るまで（扉・足音などの音の後）は上と
    同じ測り方になり、最初の 1 回の発話を取りこぼしうる
  - ゲートでないマイクでも、ミュートや USB の瞬断で一度だけ「音のあとに 0」が出るとゲートと見誤る。
    0 の部屋とみなした窓が上限まで鳴り続けたら見誤りとして見分け直すので、うるさい部屋でも
    打ち切りは 1 窓で止まる
- 頭に残すのは**最初に声と判定したコマの 0.25 秒前から**（`vad.pre_roll_ms`）。判定を待ったぶんまで
  残すと頭が長くなり、短い数字が頭の雑音に吸われる（頭 0.25 秒で「二」0.81 → 0.45 秒で 0.53）
- 最初に声と判定したコマを**1 回重ねて語頭を 20ms 引き延ばす**（`vad.onset_repeat_frames`）。
  直す前の録音ループは書き間違いでこのコマを 2 回入れていて、それが 1 拍の数字を助けていた
  （外すと「ごばん」の「五」0.79 → 0.65）。意図した動きとして残した

合成音声（-26 dBFS）を 0.8〜3.2 秒の時刻に流した 16 本での比較:

| 周りの音 | 直す前: 声の前で始まった / 途中で切れた | 直した後 |
|---|---|---|
| 静か -60 / 空調 -50 dBFS | 0 / 0 | 0 / 0 |
| 空調 -45 / -40 / -35 dBFS | **16/16 / 13〜16 本が上限で打ち切り** | 0 / 0（始まりは声の 0.1 秒後） |
| 近くの雑談（声より 10〜20dB 小さい） | 14/16 | 12〜13/16（変わらない） |

**近くの雑談は音の大きさだけでは区別できない**（`speech_margin_db` を 12・15 に上げても雑談は
減らず、空調 -40 以上で声の途中で切れ始めた）。雑談で録音が始まると、認識している間（Pi で
1 秒前後）はマイクが閉じていて、その間に話し始めた声の頭が欠ける。マイクを開けたまま認識中の
音を次の窓へ回せば欠けないが、画面が切り替わった後に古い音を新しい画面の語彙で読む危険が
あるので入れていない（実機で雑談の多い場所で困ったら検討する）。

### 「にばん」だけ反応しない

実機で、ロッカーの「にばん」だけが反応しなかった（2026-10-01・取り違えではなく反応しない）。
合成音声でも再現した。「二」は 1 拍で鼻音から始まる、いちばん弱い数字で、**静かな所でも
「二」だけ信頼度が 0.75〜0.85 に落ち、合格ライン 0.85 にわずかに届かないことがある**（「番」は 1.0。
本番と同じ流れの計測では 0.83 前後が並び、独立の検証では 90 本中 14 本が 0.75〜0.85、12 本が 0.75 未満）。
直したこと:

- **数字の語（一〜十・「一番」）だけ合格ラインを 0.75 に下げる**（`command.number_min_conf`）。
  ほかの語は 0.85 のまま。下げるほど別の数字との取り違えが増えうるので、増え方を測って決めた
- 「二」が選択肢にある画面では、同じ音の言い添え「に」を語彙に入れない（信頼度が割れる）

周りの音を重ねて本番と同じ VAD・照合（聞き直し込み）に通した、ロッカー番号 672 本:

| | 計 | 取り違え | にばん（静か / 空調 -45 / 雑談） |
|---|---|---|---|
| 直す前 | 478 | 11 | 28 / 2 / 6（計 36/96） |
| 直した後 | 473 | **8** | **31 / 5 / 8（計 44/96）** |

（`vad.py`・`defaults.py` のコメントの数字は、それぞれ「語頭の 1 コマ重ねの有無」「VAD を通さない 1792 発話」の
別の計測。独立の検証でも、静かな所の「にばん」90 本は 80 → 86・取り違え 0、白色雑音 -45 では当たり
29 → 43 と引き換えに取り違え 2 → 8（すべて「三番」）だった。）

空調 -45（白色雑音）では「よんばん」「ごばん」が下がった（31→22・31→24）。直す前は窓を開けた
時点から 3 秒をまとめて認識に回していて、雑音に慣れる間があったため（＝上の打ち切りの不具合
そのもの）。この計測は声を窓の早い時点に置いているので、直す前の打ち切りの損は数字に出ていない。
試して効かなかったもの: 聞き直しの結果の読みそろえ（「に 番」「四 万」→ 数字＋番。そろえた後の
「番」の信頼度が低く当たりにならない）、頭を 0.1〜0.15 秒に縮める、`speech_margin_db` を上げる。

**合成音声は人の声でもロビーの音でもない。** 決めるのは実機・実際のロビーで測った値。

## 6. マイクと調整

USB マイクのカード番号は挿し位置で変わるので、設定に番号を焼き込まない。サービスは
「設定の指定 → 1 秒テスト録音 → 駄目なら見つかった順（USB 優先）」で毎回決める。
使っているデバイスは status の `microphone.detail` に出る。

**マイクの入力レベルがいちばん効く**（2026-10-01 の実地試験）。安い USB マイク（USB PnP Sound Device）は
声の山でも -52〜-65 dBFS しか無く、Vosk が何の語も返さなかった（46 回中 1 回）。VAD は暗騒音との差で
区切るので録音はできていて、外から見ると「近づかないと認識しない」になる。

- サービスは認識の前に声の大きさをそろえる（`command.level_target_db` -20・最大 +30dB。46 回中 32 回まで回復）
- それでも小さい入力では語尾の母音や「ん」が崩れる（「いいえ」→「いい」、「さんばん」→「そう だ」）。
  **OS 側の録音レベルを上げるのが本筋**: Raspberry Pi は `alsamixer -c <カード番号>`（F4 で録音側）か
  `amixer -c <カード番号> sset Mic 100%`、Windows は「設定 → システム → サウンド → 入力」の入力音量
- 測り方: `scripts/voice_fieldtest.py`（案内どおりに話すと、言葉ごとの当たりと声の大きさを出す。
  録音を手元に残すので、あとから `voice_command_eval.py --no-say --wav-dir` で測り直せる）
- **入力が小さいと誤爆も増える**。持ち上げると、Vosk に聞こえていなかった小さい雑談も聞こえるように
  なる（独立の検証で、うるさめの部屋に小さい雑談を混ぜると 224 件中 19〜25 件。通常の大きさの雑談は 7〜8 件）。
  これは S/N が下がったぶんで、持ち上げのせいではない（同じ S/N で声を通常の大きさにしても同じ数）。
  OS の録音レベルを上げても同じなので、**ロビーの実際の雑談で誤爆を測ること**（§7）。特に「やめる」が
  文中に出る雑談（「やめるって言ってたよ」）は、うるさいと文の一部と見分けにくい

```yaml
# voice_input.yaml(雛形は voice_input.yaml.example)
audio:
  device: default          # マイクが複数あるときだけ名指し(plughw:CARD=Device,DEV=0 など)
  input_gain: 1.0          # 小さすぎるマイクの救済(VAD にも効く)。まず OS の録音レベルを上げる
vad:
  speech_margin_db: 9.0    # 小さい声を拾わない → 下げる(上げても近くの雑談は減らない・§4)
  onset_ms: 100            # 物音で聞き始める → 上げる(短い「はい」を取りこぼさない範囲で)
command:
  min_conf: 0.85           # 上げると誤爆が減り、取りこぼしが増える
  number_min_conf: 0.75    # 数字の語だけの合格ライン。番号が反応しない → 下げる / 取り違える → 上げる
  level_target_db: -20.0   # 認識の前に声の大きい所をこの大きさへそろえる
  level_max_gain_db: 30.0  # そのとき持ち上げる上限。0 にするとそろえない
  fallback_min_conf: 0.4   # ロッカーの番号を聞き直したときに採る信頼度
  trailing_unk_sec: 0.25   # 文の一部とみなす長さ
  silence_sec: 0.7         # 話し終わりとみなす無音
  window_sec: 8.0          # 1 回の窓の長さ(過ぎたら黙って開け直す)
```

優先順位は **既定値（`voice/defaults.py`）→ YAML → 環境変数 `VOICE_*`** の後勝ち。

言葉を足す・変えるときは `kiosk.html` の `VOICE_VOCAB` を直し、
`tests/voice_input/test_voice_command.py`（辞書の語で書けるか・同じ画面で重ならないか）と
`scripts/voice_command_eval.py` を回す。**辞書の語で書けない言い回しはサービスが黙って落とす**
（ログに「発音辞書の語で書けないため受け付けられない言い回し」と出る）。

```bash
mkdir -p ~/cmd_wavs
# 1) ロビーで 5 分録る(誰も端末に話しかけていない状態。会話・空調・足音)
```

## 12. 英語対応（表示言語の切替えに声も追従）

キオスク画面の下部帯に「EN／日本語」のタッチ切替えがある（キオスク画面の該当節を参照）。
**声で「English」「にほんご」と言わせて自動判定する方式は採用していない**
（相手の言語が分からない来訪者の発話を、どちらの言語のモデルで聞けばいいか決められない
鶏卵問題になる）。タッチ切替えを正とし、音声はその時点の表示言語に追従するだけ。

### モデル選びで分かったこと

英語の小型 Vosk モデル（`vosk-model-small-en-us-0.15` / `-zamia-0.5`、ともに 40〜50MB）は
**`graph/words.txt` に語彙外（OOV）を表す `[unk]` が無い**。日本語のモデルはこの `[unk]` を
持っているので、語彙を絞っても周りの雑談は `[unk]` として捨てられる（§4）。英語の小型モデルには
その逃げ場が無く、**周りの雑談まで高い信頼度（1.0）で選択肢に化けた**（実測:
「where did I put the locker key」が全語 conf 1.0 で「locker delivery locker cancel」に）。

`[unk]` を持つ `vosk-model-en-us-0.22-lgraph`（130MB）だけが日本語と同じ動きをした
（同じ発話が「[unk] locker [unk]」に正しく分かれ、embedded 判定で捨てられた）。
Raspberry Pi 4（4GB）以上なら容量・メモリともに問題ない大きさなので、これを既定にした
（`kiosk_agent/scripts/fetch_voice_models.py` の `ASSETS`）。

### 導入（OTA で自動配布・手動も可）

**日本語モデル(50MB)とは違って、英語モデルは OTA でも配る。** Git LFS 管理
（`.gitattributes` の `voice_models/*.zip`）で `backend/app/api/kiosk.py` の
`BUNDLE_FILES`・`kiosk_agent/updater.py` の `MANAGED_FILES` に載っている。何もしなくても
端末の定期チェック（既定60秒おき。`voice/server.py` の `_watch_models`）で zip が届き次第
自動で展開される。導入直後の端末が英語で使えるようになるまでの流れ:

1. OTA が `voice_models/vosk-model-en-us-0.22-lgraph.zip` を他のファイルと同じ経路で配る
   （`updater.py` がハッシュ差分を見て取り寄せ、`apply()` で `voice_models/` へ上書き配置）。
   130MB あるので弱い回線では取り寄せに数分かかることがある(ファイルサイズに応じて
   タイムアウトを伸ばしてある)。
2. `voice/vosk_engine.ensure_models_extracted()` が起動時・定期チェック(同じく既定60秒おき)
   の両方で zip の有無を見て、初回だけ展開する（展開済みなら何もしない・軽い）。
3. 展開が終われば `vosk_engine.available("en")` が true になり、`GET /voice/status` の
   `languages.en.available` も true になる。キオスク画面は自前でこれをポーリングしている
   ので、来訪者が操作しなくても自然に使えるようになる。

**待たずに今すぐ使いたいとき**や、OTA が届く前に動作確認したいときは手動導入もできる:

```bash
cd ~/mokuture/kiosk_agent
bash scripts/install_voice.sh --english    # 日本語に加えて英語モデル(130MB)も取得・展開
sudo systemctl restart mokuture-voice
curl -s http://127.0.0.1:8181/voice/status | python3 -m json.tool   # languages.en.available を確認
```

Windows 開発機では `scripts\install_voice_windows.ps1 -English`。

**Git LFS の実体配信の注意**: 本番(Render)は `kiosk_agent/` をビルドコンテキストに含まないため
GitHub の public raw から取り寄せる(「キオスクOTAが壊れていた」節参照)。ただし
**LFS 管理ファイルは `raw.githubusercontent.com` だとポインタ文字列(約130バイト)しか返らない**。
`backend/app/api/kiosk.py` の `_read_bundle_bytes` は `voice_models/*.zip` だけ
`media.githubusercontent.com`（公開リポジトリの LFS 実体を返す別ホスト）を使い、
念のためポインタ文字列を検知したら(ローカル・GitHub どちらでも)キャッシュ・配信しない
ようにしてある(`_is_lfs_pointer`)。新しい LFS 管理ファイルを OTA 対象に追加するときは
`_LFS_BUNDLE_PATHS` にも追記すること。

### 設定・実装

- 設定は `vosk.*`（日本語・既存のまま）とは別の節 `vosk_en.*`（`voice/defaults.py`）。
  ネストしていない＝既存の `voice_input.yaml`/`VOICE_VOSK__MODEL_PATH` は変わらず日本語を指す。
- `vosk_engine.py` の関数はすべて `lang: str = "ja"` を取る（既定は今までどおり日本語）。
  モデル・認識器・辞書キャッシュは言語ごとに分けて持つ。
- 数字の語（`command.number_min_conf` が効く語）・同音の言い添え（`_SAME_SOUND`）・フィラー
  （`command.fillers_en`）は英語専用に用意した。**フィラーに "the"/"a"/"it"/"to" のような
  極めてよく使う語を入れてはいけない**——実測で、無関係な雑談「what a nice day today
  isn't it」が「to/it」をフィラーとして認識したせいで前後が `[unk]` にならず、embedded 判定
  （文の一部を捨てる）を素通りして「visit」に誤爆した（confidence 0.904）。日本語の
  「えー／えっと／あの」に当たる間投詞と please だけに絞ってある。
- `POST /voice/session/{id}/command` の body に `lang`（省略時 `ja`）を追加。**セッションには
  言語を持たせず、1 回の聞き取りごとに渡す**——表示言語の切替えは受付の途中でも起こるので、
  セッションを張り直さずに言語だけ切り替えられるようにしてある。
- `GET /voice/status` に `languages: {ja: {...}, en: {...}}` を追加（既存のキーは変えていない）。
  英語モデル未導入の端末では `languages.en.available` が `false` になり、英語表示でも
  「声で操作する」の帯を出さない（タッチは使える）。
- `kiosk.html` の `VOICE_VOCAB` は各項目に `sayEn`/`labelEn` を持つ。表示言語を切り替えると
  `vcRelang()` が聞き取り中の語彙をその場で英語/日本語へ差し替える（画面は再描画しない
  =かざす面のカメラ・呼び出し中のポーリング・受付フォームの入力中の値を壊さない）。

### 実測（合成音声・Windows の en-US ボイス）

`scripts/voice_command_eval.py --lang en` で全画面を測った結果（しきい値 0.85）:

| | 当たり | 取りこぼし | 取り違え | 誤爆 |
|---|---|---|---|---|
| 計(258件・11画面) | 258/258 | 0 | 0 | 14/308 |

誤爆 14 件はすべて「雑談の文に語彙の単語がそのまま入っている」もの（例:
「someone said to cancel it」→ やめる、「the meeting is at three」→ 三番）。これは日本語の
実測（§4）でも同じ種類の誤爆が許容されている（「ちょっと待って」→ つづける 等、
意味としては通っている）のと同じ扱いでよいと判断した。

**合成音声は人の声でもロビーの音でもない。** 英語のしきい値（`min_conf` 等）は
ひとまず日本語の既定値を流用している。実機・実際の声での実測はまだ済んでいない
（日本語と同じく、§7 の手順で測って `command.fillers_en`/`number_min_conf` 等を調整すること）。

画面からは「声で操作する」が消え、従来のタッチ操作だけになる。
